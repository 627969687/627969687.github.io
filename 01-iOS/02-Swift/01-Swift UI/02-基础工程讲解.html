2. 关于APP协议 ​

App 协议是 SwiftUI 定义的 “应用程序入口规范”，相当于 UIKit 中 UIApplicationDelegate（应用代理）的角色，但设计更简洁。它的有三个：

  1. 标记应用入口：告诉系统 “这是程序的启动点”（配合 @main 关键字）。
  2. 定义应用结构：规定应用启动时要显示的 “场景”（窗口容器，如 WindowGroup ，通过body 属性管理）。
  3. 管理生命周期：提供监听应用前台 / 后台状态变化的能力（需另外实现一个变量获取当前状态）

2.1 必须实现的body属性 ​

App 协议必须实现body

swift
struct SwiftUIStudyAppApp: App {
    // 必须实现：返回一个“场景”（Scene）
    var body: some Scene {
        WindowGroup {
            ContentView()
        }
    }
}

  1. 作用：body 是 App 协议的 “核心义务”，用于定义应用启动后要显示的内容。
  2. 类比 UIKit：相当于 UIApplicationDelegate 中 application(_:didFinishLaunchingWithOptions:) 方法的核心作用，告诉应用启动后要显示什么界面。
  3. 返回值：必须返回 some Scene（某种场景），通常是 WindowGroup（最常用的窗口容器），里面包含根视图（如 ContentView）。

2.3 如何管理生命周期（Scene） ​

在 UIKit 中，我们通过 AppDelegate 的代理方法（如 applicationDidEnterBackground）监听应用状态变化。而 SwiftUI 的 App 协议通过定义环境变量和响应式监听在Scene场景下实现相同功能。

SwiftUI（scenePhase）UIKit（AppDelegate）触发时机
.activeapplicationDidBecomeActive(_:)应用进入前台，用户可交互
.inactiveapplicationWillResignActive(_:)应用即将进入后台（如来电、切应用）
.backgroundapplicationDidEnterBackground(_:)应用进入后台
swift
import SwiftUI

@main
struct SwiftUIStudyAppApp: App {
    // 1. 通过定义环境变量获取当前场景状态（类似UIKit的应用状态）
    @Environment(\.scenePhase) private var scenePhase
    
    var body: some Scene {
        WindowGroup {
            ContentView()
        }
        // 2. 监听状态变化（类似UIKit的代理方法）
        .onChange(of: scenePhase) { oldPhase, newPhase in
            switch newPhase {
            // 应用进入前台（对应UIKit的applicationDidBecomeActive）
            case .active: 
                print("应用激活，用户可交互")
			// 应用暂时不可交互（对应UIKit的applicationWillResignActive）
            case .inactive: 
                print("应用即将进入后台")
			// 应用进入后台（对应UIKit的applicationDidEnterBackground）
            case .background: 
                print("应用在后台，可能被终止")
            @unknown default: break
            }
        }
    }
}
