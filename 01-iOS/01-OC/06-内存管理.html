1. 内存布局 ​

布局类型存储内容特点
保留
代码段（__TEXT）编译后的可执行代码
数据段(__DATA)-常量区常量数据
1. 只读
2. 程序加载时初始化
3. 生命周期贯穿整个程序运行
数据段(__DATA)-全局区/静态区1. 未初始化的全局、静态变量等（全局区静态区 .bss）
2. 初始化的全局、静态变量等（全局区静态区 .data）		1. 全局变量在程序启动时分配，程序结束时释放
2. 静态变量在第一次使用时分配，程序结束时释放
堆对象1. 通过alloc、malloc、calloc、new等动态分配内存，需要free自行释放内存
2. 内存向高地址扩展（分配的内存空间地址越来越大，不连续，链表结构）
3. 遵循FIFO原则（先进先出）
4. 一般是0x6开头
栈局部变量、函数参数等1. 自动分配内存，运行时分配
2. 内存向低地址扩展
3. 遵循FILO原则（先进后出）
4. 一般是0x7开头

内存布局的内存地址由低到高排序： 保留 --> 代码段 --> 数据段 --> 堆 --> 栈

2. static 静态修饰符 ​

  1. 全局变量：static修改全局变量的作用域，使该全局变量仅在当前文件使用
  2. 局部变量：static修改局部变量的生命周期，使该局部变量存储在数据段，直到程序结束时销毁

3. tagged pointer ​

  1. 用于优化一些数据的内存存储方式，数据的读取直接在内存地址上
  2. 一个对象至少需要8字节，对NSNumber、NSString等类型数据来说会浪费内存
  3. 只有64位系统可用
  4. 内存地址结构：Tag+Data，Tag是类型，Data是值
  5. 分析tagged pointer内存地址需要在xcode中关闭其数据混淆

关闭混淆，设置环境变量OBJC_DISABLE_TAG_OBFUSCATION为YES

objc_tag_index_t 支持的类型值值（16进制）
OBJC_TAG_NSAtom0000
OBJC_TAG_11001
OBJC_TAG_NSString2010
OBJC_TAG_NSNumber3011
OBJC_TAG_NSIndexPath4100
OBJC_TAG_NSManagedObjectID5101
OBJC_TAG_NSDate6110
OBJC_TAG_RESERVED_77111

4. 对象的内存管理 ​

  1. iOS的内存管理主要是通过引用计数机制回收内存
  2. arm64之前（isa不是nonpointer），引用计数存储在SideTable结构体中

4.3 ARC ​

ARC：自动引用计数，开发者无需关注引用计数的个数，只需要关注强弱引用

当一个对象没有任何强引用指向时，才会被释放

函数作用
__strong 强引用被强引用指向的对象不会被无故释放，被释放时需要自行保证已经置为nil，否则容易出现野指针
__weak 弱引用被弱引用指向的对象在释放时会被自动置为nil，防止野指针

6. autoreleasepool 自动释放池 ​

  1. 把内存释放统一放在runloop的某个时机
  2. 可以使用修饰符__autoreleasing定义对象，让其加入自动释放池
  3. ARC中，如[NSArray arrayWithObject:@"1"]等不通过正常初始化的方法生成的对象会自动调用autorelease加入释放池
  4. ARC中，alloc、new、copy、mutableCopy创建出来的对象自动插入release，无需加入autoreleasepool

6.1 原理 ​

  1. 自动释放池的主要底层数据结构是：__AtAutoreleasePool结构体、AutoreleasePoolPage类
  2. 调用了autorelease的对象最终都是通过AutoreleasePoolPage对象来管理的
  3. AutoreleasePoolPage是一个通过push和pop管理的内存管理栈，FILO原则

6.1.1 AutoreleasePoolPage ​

cpp
id *begin() { // AutoreleasePoolPage地址 + AutoreleasePoolPage的大小
	return (id *) ((uint8_t *)this+sizeof(*this));
}

id *end() { // AutoreleasePoolPage地址 + SIZE(4096)
	return (id *) ((uint8_t *)this+SIZE);
}

objc
struct AutoreleasePoolPageData
{
#if SUPPORT_AUTORELEASEPOOL_DEDUP_PTRS
    // 用来优化同一对象多次加入 AutoreleasePoolPage，只需记录其地址与数量，无需重复递增，节省空间
    struct AutoreleasePoolEntry {
        uintptr_t ptr: 48;
        uintptr_t count: 16;
        static const uintptr_t maxCount = 65535; // 2^16 - 1
    };
#endif
	magic_t const magic; // 对当前 AutoreleasePool 完整性校验
	__unsafe_unretained id *next; // 指向下一个即将产生的 autorelease 对象的位置，同一对象autorelease执行AutoreleasePoolEntry
	pthread_t const thread; // 关联的线程
	AutoreleasePoolPage * const parent; // 指向父节点
	AutoreleasePoolPage *child; // 指向字节点
	uint32_t const depth; // 链表的深度
	uint32_t hiwat; // 水位线(DEBUG 使用，用作判断上次和这次的对象增加数量)
};

class AutoreleasePoolPage : private AutoreleasePoolPageData
{
public:
	static size_t const SIZE = PAGE_MIN_SIZE; // 每个 Page 的大小，为 4096 字节(虚拟内存一页的大小)
private:
	static pthread_key_t const key = AUTORELEASE_POOL_KEY; // 关于 AutoreleasePool 的 Key，用来查找存储在 TLS 中线程的 HotPage
	static uint8_t const SCRIBBLE = 0xA3; // 释放对象后用 0xA3A3A3A3 占位
	static size_t const COUNT = SIZE / sizeof(id); // 存储对象个数
  static size_t const MAX_FAULTS = 2; // 最大错误数量(DEBUG 使用)
}

6.1.2 AutoreleasePoolPage::push() ​

  1. 通过AutoreleasePoolPage::push() 创建一个自动释放池，实际上是插入一个 POOL_BOUNDARY （哨兵对象）
  2. hotPage，其存储在 TLS 中，表示当前正活跃的 Page
  3. coldPage，指向的是双向链表的头节点
cpp
static inline id *autoreleaseFast(id obj) 
{
    AutoreleasePoolPage *page = hotPage();
    if (page && !page->full()) {
        return page->add(obj); // 这里的obj就是POOL_BOUNDARY
    } else if (page) {
        return autoreleaseFullPage(obj, page);
    } else {
        return autoreleaseNoPage(obj);
    }
}

  1. 存在 hotPage 并且 hotPage 未满
    1. 直接调用 hotPage 的 add 实例方法，判断是否利用 AutoreleasePoolEntry 类型优化同一对象的多次 autorelease，否则直接加入
  2. 存在 hotPage 并且 hotPage 已满
    1. 从 hotPage ，遍历找一个未满的子节点，若没有则创建一个 AutoreleasePoolPage ，随后将找到或生成的 page 置为 hotPage （利用 TLS 机制），并将对象 add 到 hotPage 中
  3. 不存在 hotPage
    1. 创建一个 AutoreleasePoolPage ，将其设置为 hotPage，并将对象加入到 hotPage 中

6.1.3 AutoreleasePoolPage::pop(ctxt) ​

  1. 函数的调用需要传入push返回的POOL_BOUNDARY （哨兵对象）的内存地址
  2. 从hotPage到coldPage再到各节点遵循FILO原则依次销毁整个释放池
cpp
static inline void
// token就是`push`返回的`POOL_BOUNDARY` （哨兵对象）的内存地址
pop(void *token)
{
    AutoreleasePoolPage *page;
    id *stop;
    if (token == (void*)EMPTY_POOL_PLACEHOLDER) {
        page = hotPage();
        if (!page) {
            // 如果整个自动释放池为空，仅有占位符，以 nil 填充
            return setHotPage(nil);
        }
        // 从头节点开始，移除自动释放池中的所有内容
        page = coldPage();
        token = page->begin();
    } else {
        page = pageForPointer(token);
    }

    stop = (id *)token;
    return popPage<false>(token, page, stop);
}

static AutoreleasePoolPage *pageForPointer(uintptr_t p) 
{
    AutoreleasePoolPage *result;
    uintptr_t offset = p % SIZE;

    ASSERT(offset >= sizeof(AutoreleasePoolPage));

    result = (AutoreleasePoolPage *)(p - offset);
    result->fastcheck();

    return result;
}

6.2 与runloop的关系 ​

  1. iOS在主线程的Runloop中注册了2个Observer
  2. 第1个Observer监听了kCFRunLoopEntry事件，会调用objc_autoreleasePoolPush()
  3. 第2个Observer：
    1. 监听了kCFRunLoopBeforeWaiting事件，会调用objc_autoreleasePoolPop()、objc_autoreleasePoolPush()
    2. 监听了kCFRunLoopBeforeExit事件，会调用objc_autoreleasePoolPop()

6.3.2 常驻线程 ​

  1. 子线程也会有自己的autoreleasepool，会在子线程销毁时释放
  2. 线程常驻的情况下，就需要自行再增加一个autoreleasepool用于提前释放
swift
class KeepAliveThreadManager {
    private init() {}
    static let shared = KeepAliveThreadManager()

    private(set) var thread: Thread?

    /// 开启常驻线程
    public func start() {
        if thread != nil, thread!.isExecuting {
            return
        }
        thread = Thread {
            autoreleasepool {
                let currentRunLoop = RunLoop.current
                // 如果想要加对该RunLoop的状态观察，需要在获取后添加，而不是等到启动之后再添加，
                currentRunLoop.add(Port(), forMode: .common)
                currentRunLoop.run()
            }
        }
        thread?.start()
    }

    /// 关闭常驻线程
    public func end() {
        thread?.cancel()
        thread = nil
    }
}

class Test: NSObject {
    func test() {
        if let thread = KeepAliveThreadManager.shared.thread {
            perform(#selector(task), on: thread, with: nil, waitUntilDone: false)
        }
    }

    @objc
    func task() {
        /// 在任务外加一层 autoreleasepool
        autoreleasepool {

        }
    }
}
